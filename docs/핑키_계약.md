# 핑키 ↔ 관제(FMS) 계약

관제가 핑키에 요구하는 통신 규격과 동작입니다(2026-11-06).

- 이름, 타입, QoS의 원본은 `interfaces/fleet_interfaces/contract.yaml`입니다.
- `{pinky}` = `pinky1`, `pinky2`, `pinky3`. 같은 ROS 도메인에서 로봇마다 namespace를 씁니다. DDS는 Fast DDS입니다.
- **추가** 표시와 (파트 n) 표시는 아직 정의 파일이나 관제 코드에 없는 항목입니다. 지금 관제는 그렇게 동작하지 않습니다. 표시된 지시서 파트에서 정의 파일과 관제 코드에 함께 넣습니다. `BLOCKED`, `LOCALIZING`, `HEARTBEAT_LOST`는 파트 4에서 넣었습니다.
- 숫자 중 "추정"은 실측 뒤 조정합니다.

## 1. 연결

| 이름 | 타입 | 방향 | QoS·주기 |
|---|---|---|---|
| `/{pinky}/state` | 토픽 `fleet_interfaces/msg/RobotState` | 핑키 → 관제 | best_effort, volatile, depth 5. **10 Hz** |
| `/{pinky}/move_to` | 액션 `fleet_interfaces/action/MoveTo` | 관제 → 핑키 | 액션 기본값 |
| `/{pinky}/dock` | 액션 `fleet_interfaces/action/Dock` | 관제 → 핑키 | 액션 기본값 |
| `/fleet/heartbeat` | 토픽 `std_msgs/msg/Header` | 관제 → 핑키 | best_effort, volatile, depth 5. 2 Hz |

## 2. 메시지

**RobotState** (핑키가 보냄)

| 필드 | 값 |
|---|---|
| `robot_id` | 자기 이름을 넣습니다. 토픽 이름과 다르면 관제가 버립니다(빈 값은 지금은 받지만 쓰지 않습니다) |
| `pose` | `lane_map.yaml`과 같은 지도 좌표(x, y는 m, theta는 rad) |
| `battery` | 표시만 합니다 |
| `state` | `IDLE`, `MOVING`, `DOCKING`, `DOCKED`, `ERROR`, `BLOCKED`(4절), `LOCALIZING`(3절 6번). `WAITING`은 정의에 있지만 쓰지 않습니다 |
| `current_goal` | 실행 중인 목표의 `target_id`나 `dock_id`. 목표가 없으면 빈 값 |
| `stamp` | `pose`를 잰 시각 |

**MoveTo** (관제가 보냄)

| 부분 | 필드 |
|---|---|
| Goal | `target_id`(지점 ID), `target_pose`(Pose2D) |
| Goal | **추가** `geometry_msgs/Pose[] path`(파트 7): 레인 폴리라인. 첫 점은 로봇이 있는 지점, 마지막 점은 `target_pose`. 비어 있으면 `target_pose`로 갑니다 |
| Result | `success`, `reason` ∈ `NAV_ABORTED`, `CANCELED`, `TIMEOUT`, `HEARTBEAT_LOST`(3절 5번) |
| Feedback | `distance_remaining` |

**Dock** (관제가 보냄)

| 부분 | 필드 |
|---|---|
| Goal | `dock_id` ∈ `WORK`, `OUTBOUND` |
| Result | `success`, `error_x_cm`, `error_y_cm`, `error_yaw_deg` |
| Feedback | `phase` |

**Heartbeat**: `frame_id`=`fleet_manager`. 시간은 `stamp`가 아니라 받은 시각으로 잽니다.

## 3. 핑키가 지킬 것

1. **선점**: 목표를 실행하는 중에 새 목표(move나 dock)가 오면 받아들입니다. 이전 목표는 `success=false`로 끝냅니다(move_to는 `reason=CANCELED`). 정상 상태에서는 새 목표를 거절하지 않습니다. 관제는 목표를 늘릴 때 이전 목표를 취소하지 않고 새 목표를 보냅니다.
2. **취소**: 취소를 받으면 멈추고 결과를 꼭 돌려줍니다(`success=false`. move_to는 `reason=CANCELED`도 넣습니다. Dock 결과에는 reason이 없습니다). 같은 취소가 1초마다 다시 올 수 있습니다.
3. **실패**: 갈 수 없으면 결과 없이 멈춰 있지 않습니다. `NAV_ABORTED`나 `TIMEOUT`을 돌려줍니다.
4. **도착**: move_to 성공은 목표에서 **0.15 m 안**에 섰을 때만 보냅니다. 성공을 보낸 뒤 1초 안에 그 위치를 보고합니다.
5. **heartbeat**: move나 dock을 실행하는 중에 heartbeat도 새 목표도 **1.5초** 동안 오지 않으면 스스로 멈춥니다. move_to는 `reason=HEARTBEAT_LOST`로 끝냅니다. heartbeat는 비상 정지가 아닙니다.
6. **시작**: 액션 서버를 먼저 띄웁니다. 위치가 잡히기 전에는 `LOCALIZING`으로 보고하고, 잡히면 지점 위에서 `IDLE`로 보고합니다. 관제는 `LOCALIZING`인 로봇을 지도에 올리지 않고, 그 보고의 자세는 쓰지 않습니다. 지도에 오른 뒤 `LOCALIZING`이 3초 이어지면 `COMM_LOST`로 보고, 위치를 다시 보고하면 확인 뒤 이어 갑니다.
7. **주행**(파트 7): `path`가 있으면 Nav2 FollowPath로 그 선을 따릅니다. 선 밖으로 돌아가지 않고, Spin이나 BackUp 같은 복구 동작을 쓰지 않습니다.
8. **도킹**: 정지 오차 ±1~2 cm. 실제 오차를 `error_*`에 넣습니다.

## 4. BLOCKED

**핑키**: 아래를 **모두** 만족하면 `state=BLOCKED`로 보고합니다.
1. `move_to` 목표를 실행 중입니다. 도킹 중에는 쓰지 않습니다.
2. 로봇이 **1초** 이상 서 있습니다(속도 0.02 m/s 미만).
3. 서 있는 이유가 경로 위 **0.5 m** 안의 물체입니다(RPP 충돌 검사나 local costmap).

핑키가 지킬 것:
- 서고 나서 **2초 안에** 보고합니다.
- 막힌 동안 `move_to` 목표를 스스로 끝내지 않습니다. 물체가 비키면 내부에서 FollowPath를 다시 보내 이어 갑니다.
- 관제가 목표를 취소한 뒤에도 물체가 그 경로 앞에 있는 동안은 계속 `BLOCKED`로 보고합니다.
- 물체가 **1초** 동안 보이지 않으면 `BLOCKED`를 끕니다(`MOVING`이나 `IDLE`).
- 물체가 아닌 이유(위치 상실, 컨트롤러 실패)로 서면 실패(`NAV_ABORTED`)를 돌려줍니다.

**관제**:

풀림 조건: 통신이 정상인 상태에서 `BLOCKED`가 아닌 보고가 연속 3번(`release_confirm_samples`) 오면 풀린 것으로 봅니다. 통신 두절이나 복구 확인이 끼면 처음부터 다시 셉니다. 5초 전과 뒤에 같은 조건을 씁니다.

| 막힌 시간 | 관제 동작 |
|---|---|
| 0~5초 | 목표를 그대로 두고 멈춤 감시는 쉽니다. 5초 전에 풀리면 목표를 다시 보내지 않습니다. 로봇이 알아서 이어 갑니다 |
| 5초(`blocked_mark_s`) | 달리던 레인을 막힘으로 표시하고(`LANE_BLOCKED`) 목표를 취소합니다. 몸이 있는 구역은 쥡니다. 아직 들어가지 않은 앞 구역은 **취소 결과가 오고 로봇이 선 것을 확인한 뒤** 놓습니다. 그때까지 새 목표를 보내지 않습니다. 다른 로봇은 돌아가거나 기다립니다. 세부는 공통설계 5절 |
| 5초 뒤 풀림 | `LANE_BLOCKED`를 낸 뒤 풀리면 `LANE_CLEARED`를 내고, 취소 결과를 받은 뒤 구역을 다시 청해 같은 목표를 다시 보냅니다. 실패 시도로 세지 않습니다 |
| 60초(`blocked_timeout_s`) | `ERROR(BLOCKED)`. 구역은 쥔 채 두고 자동 격리합니다(`ROBOT_ISOLATED`). 레인 표시는 `BLOCKED`가 아닌 보고가 오면 지웁니다 |

- **막힌 시간**: `BLOCKED`로 보고된 시간만 더합니다. 풀린 뒤 10초 안에 같은 레인에서 다시 막히면 이어 더합니다. 5초와 60초는 같은 시계입니다.
- **줄 서기는 막힘이 아닙니다**: 앞 0.6 m(`queue_gap_m`) 안에 정상인 다른 핑키가 있으면 `BLOCKED`를 막힘으로 치지 않고 멈춤 감시만 쉽니다. 줄 서기가 60초 넘게 이어지면 막힘 규칙을 씁니다. 세부는 공통설계 5절.
- **관제 출력**: 막힌 동안 `/fleet/robots`의 `fault_reason`은 `BLOCKED`, `fault`는 `NONE`입니다. 이벤트는 `LANE_BLOCKED`(WARN), `LANE_CLEARED`(INFO), `BLOCKED_TOO_LONG`(ERROR)입니다.
- 1초, 0.5 m, 2초, 5초, 0.6 m는 추정입니다. 지시서 4번은 BLOCKED를 받는 즉시 목표를 취소하라고 했지만, 잠깐 막힐 때마다 취소·재전송·우회가 일어나지 않게 5초를 두었습니다.

## 5. 관제가 하는 것

| 상황 | 관제 동작 |
|---|---|
| `state`가 3초 동안 안 옴 | `COMM_LOST`. 그 로봇의 잠금 요청을 모두 취소합니다 |
| 실패 결과 | 2초 뒤 다시 보냅니다. 세 번 실패하면 `ERROR`이고 구역은 쥔 채 둡니다 |
| 목표가 열린 채 6초 제자리(도킹은 15초) | 취소하고 다시 보냅니다(`GOAL_STALLED`). 실패 한 번으로 셉니다 |
| `BLOCKED` | 4절 표를 따릅니다. 다른 로봇은 공통설계 5절의 우회 규칙(`DETOUR`)으로 돌아가고, 길이 없으면 기다립니다 |
| `HEARTBEAT_LOST` 결과 | 실패 시도로 세지 않고 2초 뒤 같은 목표를 다시 보냅니다. 진전 없이 되풀이되면 6초 멈춤 감시가 실패 한 번으로 셉니다 |
| 지도에 오른 뒤 `LOCALIZING` | 자세를 쓰지 않습니다. 3초 이어지면 `COMM_LOST`이고 구역은 쥔 채 둡니다. 위치를 다시 보고하면 확인 뒤 이어 갑니다. 세부는 공통설계 5절 |
| 보고 위치가 달리는 레인에서 0.15 m 넘게 벗어난 것이 3번 이어짐 | 목표를 취소합니다(`LANE_ERROR`). 구역은 쥔 채 둡니다. 레인에 돌아오면 같은 목표를 다시 보냅니다(`BACK_ON_LANE`). 20초 안에 못 돌아오면 `ERROR(OFF_LANE)`입니다. 세부 예외는 공통설계 5절 |
