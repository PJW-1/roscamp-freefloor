# 관제(FMS)가 주고받는 것

관제(`fleet_manager` 노드, 관제 PC에서 프로세스 1개)가 무엇을 받고 보내는지, 결과를 어떻게 처리하는지 정리한 것입니다. 이름·타입·QoS의 원본은 `interfaces/fleet_interfaces/contract.yaml`입니다.

"(제안, 팀 합의 전)"은 아직 팀 합의 전인 바깥 인터페이스입니다.

## 1. 한 주문의 흐름

| 순서 | 관제가 하는 일 | 상대 |
|---|---|---|
| 1 | `/central/orders`에서 주문을 받는다 | central |
| 2 | 핑키를 작업공간(WORK) 도크로 보낸다 (`move_to` → `dock`) | 핑키 |
| 3 | 두 팔에게 바구니 담기를 요청한다 (`fill_basket`) | 작업공간 서버 |
| 4 | 핑키를 출고(OUTBOUND) 도크로 보낸다 | 핑키 |
| 5 | arm3에게 바구니 교환을 요청한다 (`swap_basket`) | arm3 |
| 6 | 결과를 보고한다 (`report_order`: SHIPPED, PARTIAL, HELD) | central |

- 작업공간 도크에는 핑키 1대만. 나머지는 대기 지점에서 기다린다.
- 주문 1건 = 바구니 1개(최대 4개). 결품이면 담긴 것만 출고, 하나도 못 담으면 HELD.

## 2. 관제가 보내는 것

| 이름 | 종류 | 받는 쪽 | 언제 · 한 줄 |
|---|---|---|---|
| `/{pinky}/move_to` | 액션 `MoveTo` | 핑키 | 잠금을 쥔 데까지만 보낸다. 잠금을 더 얻으면 새 목표로 늘린다(이전 목표는 교체) |
| `/{pinky}/move_to`의 `path` | 액션 필드(제안, 팀 합의 전) | 핑키 | `lane_goal_mode`가 `path`일 때 레인 폴리라인을 싣는다. 첫 점은 로봇이 보고한 위치, 끝 점은 목표 지점. `point`면 비운다 |
| `/{pinky}/dock` | 액션 `Dock` | 핑키 | 경로 끝(도크 지점)에 도착한 뒤 |
| `/workcell/fill_basket` | 액션 `FillBasket` | 작업공간 서버 | WORK 도킹 뒤. 재시도 때는 아직 못 담은 품목만 |
| `/arm3/swap_basket` | 액션 `SwapBasket` | arm3 | OUTBOUND 도킹 뒤. 재시도 때는 남은 단계만 |
| `/central/report_order` | 서비스 | central | `accepted=true`가 올 때까지 2 s마다 다시 보낸다 |
| `/fleet/heartbeat` | 토픽, 2 Hz | 핑키 | 관제가 살아 있다는 신호. HEARTBEAT 프로필(reliable, volatile, depth 1, 제안, 팀 합의 전). 전원이 지도에 오른 뒤부터 |
| `/fleet/robots` | 토픽, 1 Hz | 화면 | 로봇별 상태, 위치, 배터리, 오류 이유 |
| `/fleet/assignments` | 토픽 | 화면 | 로봇별 지금 하는 일 |
| `/fleet/zones` | 토픽 | 화면 | 구역 잠금 상태. 전원이 지도에 오른 뒤부터 |
| `/central/events` | 토픽 | 화면, central | 관제 이벤트(5절) |

## 3. 관제가 받는 것

| 이름 | 종류 | 보내는 쪽 | 관제가 쓰는 것 |
|---|---|---|---|
| `/{pinky}/state` | 토픽 `RobotState`, best_effort | 핑키 | 위치(구역 해제, 도착 확인), 상태(`MOVING`·`DOCKING`·`RECOVERING`·`BLOCKED`·`LOCALIZING`이면 시작 때 아직 지도에 안 올림). 3 s 끊기면 통신 두절. 변할 때만이 아니라 주기적으로 계속 발행해야 한다 |
| `/central/orders` | 토픽 | central | 주문 목록, run_mode(RUN, PAUSE, STOP) |
| `/fleet/confirm_clear` | 서비스 | central(관리자) | 관리자가 로봇을 치웠다 → 구역을 풀고 그 로봇을 `OUT_OF_SERVICE`로 둔다. 자동 격리된 로봇은 주문이 이미 돌아가 있어 구역만 푼다. 격리되지 않은 로봇은 주문도 대기 맨 앞으로 되돌린다. 거부하면 응답 `reason`에 이유 |
| `/fleet/reinstate` | 서비스 `Reinstate`(제안, 팀 합의 전) | central(관리자) | 치운 로봇을 다시 넣는다. `OUT_OF_SERVICE`이고 쥔 구역이 없는 로봇, `basket`이 `EMPTY` 또는 `NONE`일 때만 받는다. 받으면 `ROBOT_REINSTATED`를 내고 다음 위치 보고로 지도에 올린다. 거부하면 응답 `reason`에 이유 |
| 각 액션의 결과 | 액션 결과 | 핑키, 팔 | 4절 |

`/{arm}/state`, `/{arm}/vision/items`는 관제가 쓰지 않습니다.

## 4. 결과를 받으면

| 받은 결과 | 관제의 처리 |
|---|---|
| 이동 성공, 위치가 목표 0.15 m 안 | 도착 |
| 이동 성공, 위치가 아직 멂 | 1 s 동안 위치 보고를 기다린다. 그래도 멀면 실패 1회 |
| 이동·도킹 실패, 거절, 지금 목표의 `CANCELED` | 실패 1회. 2 s 뒤 다시 보낸다. 세 번째 시도까지 실패하면 그 로봇은 ERROR |
| 이동 실패 `PATH_NOT_CONNECTED`(제안, 팀 합의 전) | 다른 이동 실패와 같이 실패 1회. `move_retry_wait_s`(2 s) 뒤 로봇의 지금 보고 위치에서 path를 다시 만들어 보낸다. 이유는 `GOAL_RETRY`의 detail에 남는다 |
| 이동 실패 `HEARTBEAT_LOST` | 실패로 세지 않는다. `move_retry_wait_s` 뒤 같은 목표를 다시 보낸다 |
| 이동 실패 `TIMEOUT` | 다른 이동 실패와 같이 실패 1회. 핑키는 막힌 채 `block_timeout_s`(90 s, 제안)가 지나면 goal을 이것으로 끝낸다. 관제가 막힘 `blocked_mark_s`(5 s)에 goal을 먼저 취소하므로 관제가 취소하지 못했을 때의 마지막 안전장치다 |
| 교체된 이전 목표의 결과 | 무시 |
| 이동·도킹 goal이 열린 채 제자리(이동 `stall_s` 6 s, 도킹 `dock_stall_s` 15 s) | 취소하고 `GOAL_STALLED`를 낸다. 실패 1회로 세어 같은 목표를 다시 보낸다. 세 번째 시도까지 실패하면 그 로봇은 ERROR |
| 이동·도킹 결과가 오지 않음 | 로봇이 제자리면 위 멈춤 감시가 잡는다. 움직이는 동안은 시간 제한이 없어 계속 기다린다 |
| `fill_basket` success=true | `placed`, `missing`을 반영하고 끝 |
| `fill_basket` success=false | `placed`만 반영하고 남은 품목을 다시 요청 |
| 담은 것이 0개 | HELD 보고, 빈 바구니로 다음 일 |
| `swap_basket`의 `took_full`=true | 바로 SHIPPED(결품 있으면 PARTIAL) 보고 |
| 팔 작업 시간 초과(담기 90 s, 교환 60 s) | 취소를 보내고 5 s 기다린다. 결과가 없으면 ERROR(`ARM_NO_RESULT`) |
| 관제가 보낸 취소 | 결과가 올 때까지 1 s마다 다시 보낸다 |
| 취소한 로봇 goal의 결과를 잃음 | `CANCEL_UNCONFIRMED`를 낸 뒤 취소를 그만두고 그 goal을 끝난 것으로 본다. 막힘 때 취소한 goal이면 이어 간다(새 goal로 덮어쓴다) |
| 출고 도크 호출 실패(관제 안) | `dispatch_retry_wait_s`(2 s) 뒤 다시 보낸다(`DISPATCH_RETRY`). `dispatch_retry_limit`(3)을 넘으면 ERROR(`DISPATCH_FAILED`), 격리되어 주문은 대기 맨 앞으로 돌아간다. 격리된 로봇은 다시 보내지 않는다 |

## 5. 핑키 교통

| 항목 | 방식 |
|---|---|
| 길 | 레인 그래프(`lane_map.yaml`) 위 최단 경로 |
| 잠금 단위 | 지점마다 구역 하나. 지금 구역 + 다음 구역까지만 잡는다 |
| 순서 | 구역마다 먼저 청한 로봇부터 |
| 해제 | 다음 레인을 따라 0.2 m 넘게 간 위치 보고가 3번 이어지면 |
| 양방향 통로 | 통로 전체를 구역 하나로(한 번에 한 대) |
| 교착 | 서로 기다리는 고리를 찾으면 고리에 든 로봇만 세우고(밖의 로봇은 평소대로), 우선순위가 낮은 로봇이 아직 안 들어간 구역을 포기. 못 풀고 `deadlock_unresolved_s`가 지나면 그 로봇을 자동 격리 |
| heartbeat | 2 Hz. 끊긴 지 1.5 s에 핑키가 스스로 정지 명령을 낸다(제동 거리는 별도). 끊김 판단은 QoS가 아니라 핑키의 앱 타이머(`heartbeat_timeout_s`) |
| 시작 | 전원이 위치를 보고하고 `MOVING`·`DOCKING`·`RECOVERING`·`BLOCKED`·`LOCALIZING`이 아니면 지도에 올리고 움직인다 |
| 재시작 | 진행 중이던 주문·할당은 기억하지 않는다 |
| STOP / PAUSE | STOP: 이동·팔 작업 취소. PAUSE: 하던 것은 끝내고 새 명령을 내지 않음 |
| 잘못된 입력 | 코어에 닿기 전에 거른다. 서비스는 거부하고 토픽은 버리며 `INPUT_REJECTED`를 낸다. 서비스는 호출마다 한 번, 토픽은 출처마다 한 번 내고 정상 메시지가 오면 다시 낸다 |
| 거르는 입력 | 모르는 로봇, 메시지의 `robot_id` 불일치, 유한하지 않은 위치나 지도 범위에서 `input_pose_margin_m`(1 m) 넘게 먼 위치(`LOCALIZING` 보고는 위치를 안 본다), 틀린 run_mode(통째로 버림), 틀린 주문(run_mode는 적용, 주문은 이전 것 유지), 모르는 이름의 `confirm_clear`, 틀린 `reinstate` |
| 레인 이탈 | 지금 달리는 레인에서 `lane_error_warn_m`(0.15 m) 넘게 벗어난 보고가 3번 이어지면 `LANE_ERROR`를 내고 목표를 취소해 세운다. 구역은 쥐고 해제 판단을 멈춘다 |
| 레인 복귀 | 레인 위 보고가 3번 이어지면 `BACK_ON_LANE`을 내고 같은 목표를 다시 보낸다. `off_lane_timeout_s`(20 s) 안에 못 돌아오면 ERROR(`OFF_LANE`). 그동안 `/fleet/robots`는 `RECOVERING`, `fault_reason`은 `OFF_LANE` |
| 레인 막힘 | 이동 중 `BLOCKED`(제안, 팀 합의 전) 보고된 시간이 `blocked_mark_s`(5 s)가 되면 그 레인을 막힘으로 표시하고(`LANE_BLOCKED`) 목표를 취소한다. 쥔 구역은 그대로, 들어가지 않은 앞 구역은 놓는다 |
| 막힘 풀림 | `BLOCKED`도 `RECOVERING`도 아닌 보고가 3번 이어지면 `LANE_CLEARED`를 내고 같은 목표를 다시 보낸다(시도로 세지 않는다). 풀린 뒤 `blocked_rejoin_s`(10 s) 안에 같은 레인에서 다시 막히면 막힌 시간을 이어 센다 |
| 막힘 시간 초과 | `BLOCKED`로 보고된 시간이 `blocked_timeout_s`(60 s)면 ERROR(`BLOCKED`)와 `BLOCKED_TOO_LONG` |
| 줄 서기 | 같은 레인이나 다음 레인 앞 `queue_gap_m`(0.6 m) 안에 정상 로봇이 있으면 막힘으로 치지 않고 막힘 표시와 멈춤 감시를 쉰다. `blocked_timeout_s`를 넘으면 막힘으로 친다 |
| 멈춤 감시 | RUN일 때 이동·도킹 goal이 열린 채 매끄럽게 한 위치가 `stall_move_m`(0.05 m)보다 덜 움직이면 제자리로 본다. 막힘과 줄 서기 동안은 쉰다. 로봇의 `RECOVERING` 동안도 쉬고, 끝난 때부터 새로 잰다 |
| 자가 복구(제안, 팀 합의 전) | 핑키가 `RECOVERING`을 보고하는 동안 `MOVING`처럼 목표를 실행 중으로 본다. 막힌 시간을 더하지 않고 막힘 풀림 보고로도 세지 않아 5 s 표시와 60 s ERROR가 일어나지 않는다. 멈춤 감시는 쉰다. 다만 `RECOVERING`이 `self_recovery_limit_s`(45 s, 핑키의 두 번 시도는 길어야 약 35 s)를 넘으면 `SELF_RECOVERY_TOO_LONG`(WARN)을 내고 그 뒤 보고를 `BLOCKED`로 본다. 레인 이탈 감시는 그대로다. 시작과 끝에 `SELF_RECOVERY`, `SELF_RECOVERY_END`를 낸다. 핑키 쪽 규칙은 핑키 계약 4절 |
| 마지막 목표 표시(제안, 팀 합의 전) | `move_to` goal의 `final_goal`은 path 끝이 임무의 마지막 지점일 때만 참이다. 잠금 경계에서 끝나는 목표는 거짓이라 핑키가 끝에서 정밀 접근 대신 설 수 있는 속도(√(2·a·남은 거리))로만 줄인다. 끝을 넘지 않는다. 자유바닥(`traffic_mode: freefloor`)에서는 굴러가는 칸 잠금 끝에서 끝나는 MoveTo가 모두 거짓이고 경로 끝에 닿는 것만 참이다 |
| 자유바닥 접근선 시간창(제안, 기본 꺼짐) | `floor_dock_schedule: true`일 때 도크 접근선 다음 차례는 접근선 시작에 가장 빨리 닿는 로봇이다(`floor_dock_aging_s` 30 s 넘게 기다린 로봇은 먼저 온 순서). 앞 로봇이 선을 비울 예상 시각(ETA: 경로 ÷ `eta_speed_mps` + 제자리 회전 + 도킹 + 팔 작업 + `floor_leave_s`)이 이 로봇이 닿을 시각 + `floor_pre_admit_margin_s` 안이면 비기 전에 출발시킨다. 선이 빌 때까지는 제 선에만 속한 칸까지, 다른 고정 선과 주차 지점 몸 칸에 닿지 않는 자리에 서서 선에 줄을 선다. 그런 자리가 없거나 앞 로봇이 언제 비킬지 모르면(격리, 막힘, 할 일 없이 서 있음) 대기 자리에서 기다린다. 끄면 먼저 기다리기 시작한 순서(기존) |
| 자유바닥 길 찾기 | 계획(A*)은 서 있는 로봇이 쥔 칸만 벽으로 피하고, 제 길을 가는 로봇(남의 칸을 기다리지 않고, 멈추지 않았고, 고정 선 위나 설 자리에 선 게 아닌)의 칸에는 그 칸이 빌 때까지 서서 기다리는 값(시간 × `detour_speed_mps`, 비용에는 0.8배)만 문다. 그 로봇이 마주 오는 방향이면 칸마다 벌점 0.5 m다. 단 내 앞길을 마주 오는 로봇(둘의 앞길 `detour_speed_mps` × `floor_plan_window_s`가 겹치는 칸에서 120° 넘게 반대)은 벽으로 피한다. 마주 오는 로봇의 칸을 피한 길이 없거나 그 길도 마주치면, 서 있는 로봇을 벽으로 보지 않은 길이 아무와도 마주치지 않을 때 그 길을 쓴다(서 있는 로봇 앞에서 기다림). 그런 길도 없으면 피한 길, 그것도 없으면 처음 길을 쓴다. 막혀서 다시 계획할 때도 마주 오는 로봇을 만나는 길로는 돌지 않는다. 대기 자리로 가는 길은 모든 로봇을 벽으로 본다. 피할 길이 하나도 없으면(금지 칸을 더 얹지 않은 계획일 때) 피하지 않는 길로 다시 찾는다. 앞 칸을 못 잡았는데 막은 로봇이 모두 지나가는 로봇이면 `floor_pass_wait_s`(4 s, 제안) 서서 기다린 뒤 다른 길(대기 자리로 가는 중이면 다른 대기 자리)을 찾는다. 두 로봇이 서로 막으면 우선순위가 낮은 쪽(비켜 서기와 같은 순서)만 상대의 앞길 1.2 m를 피해 돌고 다른 로봇은 제 길을 지킨다. 낮은 쪽이 돌 수 없는 다리이거나 길을 못 찾았거나 4 s가 지나면 지키던 로봇도 돈다. 다른 길이 남은 길보다 3 m 넘게 길면 돌지 않고 기다리지만, `DEADLOCK_UNRESOLVED`로 고른 로봇은 격리 대신 그 길로 돈다. 안전은 칸 잠금(전부 아니면 전무)이 그대로 맡는다 다리·다시 잡기·대기 자리로 가는 길(`_route`)은 스테이션 도크의 몸 둘레 칸(도크 자리에서 몸 반지름 안)을 벽으로 더해 먼저 찾는다: 도크 옆을 지나는 길이 도킹한 로봇의 칸에서 몸 하나만큼 떨어진다. 그렇게는 길이 없으면(출발점이나 목표가 그 둘레 안일 때 포함) 그 칸을 벽으로 보지 않고 다시 찾는다. 도크로 드나드는 고정 선은 그대로이고, 비켜 서기 길에는 적용하지 않는다 |
| 자유바닥 엇갈림 양보 | 길이 엇갈리는 두 로봇(계약 속도로 달릴 때 같은 칸을 같은 시각에 씀, `floor_plan_window_s` 앞까지)은 엇갈리는 칸에 먼저 닿는 쪽이 지나간다. 시각 차가 0.5 s 안이면 우선순위가 높은 쪽(같으면 비켜 서기와 같은 순서)이다. 늦는 쪽은 먼저 갈 로봇이 엇갈리는 곳을 다 지날 때까지 쓸 칸(둘레에 `cell_margin_m`)을 잡지 않고, 줄도 서지 않고, 그 앞에 서서 기다렸다가 제 길로 간다(다시 계획하지 않음). 한 번 정한 차례는 엇갈림이 끝날 때까지 지킨다. 비켜 주지 않는 경우: 상대가 막혀 섰을 때(잠금이 안 늘거나, 남의 칸을 기다리거나, BLOCKED이거나, 접근선 앞 설 자리까지 잠갔을 때), 상대가 이미 이 로봇을 먼저 보내기로 했을 때, 차례를 정할 때 이 로봇의 몸이 이미 상대 길 위에 있을 때(좁은 데서 마주 옴), 이 로봇이 고정 선 위일 때, 기다림이 `floor_pass_wait_s` + `floor_plan_window_s`(12 s)를 넘었을 때(잠금이 늘 때까지 이어서 세고, 그 다리에서는 그 로봇에게 더 비켜 주지 않음). 길을 다시 계획하면 차례를 처음부터 정한다. 이때는 예전처럼 칸 잠금 선착순과 재계획·교착 처리가 맡는다 |
| 자유바닥 로봇 자리(보고 평균) | 자유바닥 관제는 로봇 자리를 보고 하나가 아니라 평균으로 본다: 서 있는 동안은 최근 보고 50개(평균에서 0.12 m 넘게 튀면 다시 모음), 달리는 동안은 최근 5개(0.2 m 넘게 튀면 다시). 몸 둘레 칸, 새 길의 첫 점, 보내는 path의 첫 점이 이 자리를 쓴다(path 첫 점은 길을 따라 진행점 옆으로 당김). 진행점은 보고 하나로 잰다. 자리 잡은 뒤 첫 MoveTo는 서 있는 보고 20번(또는 흔들림 없는 보고 2번) 뒤에 보낸다. 5 s 기다려도 안 모이면 `FLOOR_PLACE_UNSETTLED`(WARN)를 내고 보낸다. 다시 올린 로봇은 처음부터 센다. 서 있는 로봇은 평균 자리 둘레의 빈 칸을 채워 두고, 다리가 있어도 앞을 못 잠근 채 서 있으면 몸 둘레 칸만 쥔다. 칸은 보고 자리와 평균 자리 둘 다에서 멀 때만 놓는다. 반폭을 적은 지도에서, 서 있는 자리를 믿을 만한 로봇(서 있는 보고 20번 또는 흔들림 없는 2번)은 출발 원 둘레에서 몸이 닿을 수 없는 칸(모서리 반지름 0.085 m + 평균 오차 3σ 밖, 최소 0.09 m) 가운데 갈 길 띠 밖이고 남이 쥔 칸을 요구하지 않는다. 이탈 감시는 평균 자리의 몸 칸을 잡고, 보고 자리의 몸(반지름 `robot_radius_m`)이 남의 칸 위인 보고가 `release_confirm_samples`번 이어지면 세운다(`FLOOR_OFF_CELLS`) |

| 자유바닥 반폭 잠금(지도 `robot_half_width_m`) | 지도에 반폭이 있으면 차동구동 로봇이 곧게 달리는 동안은 옆으로 반폭 + `cell_margin_m`만 잠근다(경기장 0.06 + 0.03 m, 몸 원은 0.11 m). 제자리에서 돌 수 있는 곳은 몸 원 전체를 잠근다: 경로 출발점, 경로 끝, 꼭짓점 꺾임(절댓값)을 0.25 m(RPP `max_lookahead_dist`) 창 안에서 합쳐 0.25 rad(`eta_turn_min_rad`, RPP `rotate_to_heading_min_angle`)를 넘는 곳(첫 꼭짓점 앞 0.25 m부터 창 안 마지막 꼭짓점까지). 보고 자리 둘레는 다리 출발 뒤 0.05 m를 지나 곧게 달리는 중이면 반폭 원, 아니면 몸 원을 쥔다. 적지 않으면 늘 몸 원 |
| 자유바닥 출구선 지키기 | 도크를 나가던 로봇은 주차 칸을 다시 고르거나 다른 일을 받아 새 다리가 시작돼도, 같은 다리를 다시 계획해도 남은 출구선을 따라 나간다. 선에서 0.12 m 안이면 가장 가까운 구간 위 가장 가까운 점(대개 수직 발, 구간 밖이면 꼭짓점)에 붙고 그다음은 남은 꼭짓점을 따른다(계획한 경로는 도크로 되돌아가지 않음). 선 끝을 지났거나 선에서 멀면 바닥 위에서 계획한다. 보내는 MoveTo는 로봇 자리(보고 평균을 길을 따라 진행점 옆으로 당긴 점, '자유바닥 로봇 자리' 행)에서 경로 0.05 m 앞 점(남은 길이가 0.05 m 이하면 끝점)으로 곧게 이으므로(`_drive_path`) 그 0.05 m 안의 수직 발이나 꼭짓점은 잘라 갈 수 있다(잠금은 보낸 path를 따라 잡음). 예외: 선 시작점에서 도착 허용 거리(0.15 m) 안이면 선에서 0.12 m 넘게 떨어져 있어도 출구선을 지키고, 이때는 선 시작점부터 선 전체를 간다(도크 쪽으로 0.15 m 안에서 되돌아갈 수 있음). |
| 자유바닥 방향 표시(제안(실측 전), 지도 `passages`) | 자유바닥 지도에 양방향 통로(`passages`)가 있을 때만 쓴다(지금은 `floor_map_arena_v4_twoway.yaml`; 통로가 없는 지도는 아무것도 바뀌지 않는다). 통로마다 표시 하나 = (방향, 쥔 로봇들). 몸이 통로 가운데 선을 쓸고 가는 칸이 통로 칸이다. 잠금 끝이 통로 묶음(이어 닿는 통로들, 갈림목 포함) 0.6 m 앞에 오면 묶음의 표시를 한꺼번에 잡는다(전부 아니면 전무, 하나 쥐고 다른 것을 기다리지 않는다). 비었거나 같은 방향이면 잡고(같은 방향은 줄지어 들어간다), 반대 방향이면 입구 밖에 선다. 설 자리는 묶음 앞에서 거슬러 서 있는 몸이 반대로 쥔 로봇들의 남은 길에 닿지 않는 첫 자리다(통로 안·갈림목에서는 기다리지 않는다). 반대쪽에서 먼저 기다리기 시작한 로봇이 있으면 같은 방향 로봇도 새로 들어가지 않는다(공평, 굶지 않음). 몸이 통로 칸을 다 벗어나고 다리가 그 통로를 더 지나지 않으면 놓는다. 격리·통신 두절 로봇은 칸처럼 표시도 쥐고, `OUT_OF_SERVICE`는 놓는다. 표시 기다림은 교착 고리 찾기에 칸 기다림과 함께 들어간다. 표시는 칸 잠금을 대신하지 않는다(두 로봇이 같은 칸을 쥐지 않고 몸은 쥔 칸 밖에 서지 않는다). 기다리는 로봇은 `floor_replan_s`마다 못 잡은 통로를 벽으로 본 다른 길과 견주어, 그 길의 도착(`eta_speed_mps`)이 기다림(반대로 쥔 로봇이 묶음을 다 나갈 때까지, 격리되면 끝없음) + 남은 길보다 `floor_mark_switch_gain_s`(3 s) 넘게 빠를 때만 바꾼다(`FLOOR_MARK_SWITCH`). 작업대 대기 자리도 통로 칸에 닿지 않는 곳에서 고른다 |
| 자유바닥 지름길(제안, 기본 꺼짐, 지도 `shortcuts`) | `floor_shortcut: true`일 때만 지도에 그린 지름길을 탄다. 로봇은 접근선으로 출발하고, 잠금이 갈림길에 닿을 때 한 번 고른다: 같은 도크로 접근선을 앞서 가는 로봇이 없고, 지름길이 다른 선과 겹치는 구간 전체를 한 번에 잡을 수 있고, 도크에 있거나 떠나는 로봇이 그 구간에 닿기 전에 지나갈 수 있으면 `FLOOR_SHORTCUT`을 내고 꺾는다. 겹치는 구간 안에서는 서지 않고, 도크 앞 꼬리의 칸을 다른 로봇이 쥐고 있으면 구간 끝에서 기다린다. 끄면 관제는 지름길을 뺀 지도(그 선도, 그 선 밑의 좁은 칸도 없음)로 돈다. arena_v4의 지름길은 Gazebo에서 물체 3 모서리에 걸려(2026-11-11, 2회 중 2회) 꺼 두었다 |
| 자유바닥 교차 상자(제안, 기본 꺼짐) | `floor_junction_box: true`일 때만 한 방향 선이 만나는 갈림길(한 선이 꺾이는 점을 다른 선이 다른 쪽에서 지나는 곳)을 상자로 본다. 한 방향 선을 가는 로봇은 몸이 상자에 닿는 구간을 통째로 잡거나 그 앞에 서고, 다 지날 때까지 놓지 않는다. arena_v4에서는 갈림길 (0.97, 0.445) 한 곳이고 구간이 0.57~0.59 m라, 켜면 가운데 통로의 잠금이 0.15 m 굴림보다 훨씬 길어진다(Gazebo 1판씩: 쥔 칸 평균 128 → 217칸). 끄면 교차 상자가 없던 때와 사건·명령이 같다. |
| 조용히 선 로봇 감시(제안) | 이동 단계인데 goal도 구역 대기표도 없이 `idle_watch_s`(10 s) 서 있으면 `ROBOT_IDLE`을 내고 지금 지점 goal을 다시 보낸다. 실패 1회로 세고, 같은 자리에서 세 번째면 ERROR. 도킹·스테이션, STOP·PAUSE, 고장·두절·레인 이탈, 교착 멈춤, 막힘 중에는 보지 않는다 |
| 배터리 낮음과 충전(제안, 기본 꺼짐) | 보고한 배터리(0–100)가 `battery_low_pct` 이하면 `ROBOT_BATTERY_LOW`를 내고 그 로봇은 새 호출을 받지 않는다. 빈 채로 작업대로 가던 중이면(commit 구역 전) 호출을 내놓고 대기 지점으로 가고, 싣고 있으면 출고까지 마친 뒤 간다. 대기 지점이 충전 자리다. `battery_charged_pct` 이상을 보고하면 `ROBOT_CHARGED`를 내고 다시 받는다. 0 이하 배터리는 모르는 값이라 무시한다(실물 pinky_fsm은 배터리 토픽이 없으면 -1). 레인에서는 대기 줄이 한 줄이라 앞에서 충전하는 로봇을 뒤 로봇이 지나가지 못한다. 자유바닥은 지나간다 |
| 우회 | 다음 구역을 청할 때만 길을 다시 고른다. 비용은 레인 길이 + 서 있는 로봇이 쥔 구역의 벌점(예상 대기 시간 × `detour_speed_mps` 0.2 m/s). 새 길이 더 싸야 바꾸고 `DETOUR`를 낸다. `detour_enabled`가 false면 줄을 선다 |
| 우회로 못 지나는 곳 | 막힌 레인, 그리고 못 비키는 로봇(고장, 두절, 복구 확인, 막힘, 레인 이탈)이 쥔 구역 |
| 대기 시간 추정 | 스테이션이나 대기 칸에 선 로봇은 `station_wait_estimate_s`(30 s)로 센다. 구역을 기다리는 로봇은 기다린 시간, 줄 선 로봇은 줄 선 시간이다 |
| 대기 줄 출구 막힘 | 대기 줄은 한 방향이라, 출구 구역을 격리·`OUT_OF_SERVICE` 로봇이 쥐면 줄 밖 로봇을 줄로 보내지 않는다. 다른 출구가 남은 대기 칸이 있으면 거기까지만 쓰고, 없으면 지금 자리에서 기다린다(도크에 있으면 도크를 비우고 줄 입구 앞에서). 줄 안 로봇은 그 자리에 선다 |
| 자동 격리 | 지도에 오른 로봇이 ERROR가 되면 한 번 격리한다. 구역은 쥐고, 열린 요청과 목표는 취소하고, `ROBOT_ISOLATED`를 내고, 그 로봇의 주문은 대기 맨 앞으로 되돌린다(`ORDER_REQUEUED`). 바구니는 `NONE`으로 본다. 다른 로봇은 그 구역을 비켜 간다 |
| 격리 때 주문을 두는 경우 | 교환 중이면 그 결과가 올 때까지, `ARM_NO_RESULT`로 쥔 주문은 `confirm_clear`까지 주문을 둔다 |
| 재투입 | `/fleet/reinstate`를 받으면 로봇의 기록을 새로 만들어 지도 밖에 둔다. 다음 위치 보고로 시작 때와 같은 절차로 오른다. 그동안 다른 로봇은 멈추지 않는다 |
| 재투입 충돌 | 남이 쥔 구역에서 보고되면 `PLACEMENT_CONFLICT`를 내고 그 구역의 주인을 세운다. 우회 판단에서는 못 비키는 로봇이다 |
| 경로 첫 점 | `path`의 첫 점은 늘 로봇이 보고한 위치다. 그래서 위치 잡음이 0.15 m보다 훨씬 작으면 정상 운행에서는 `PATH_NOT_CONNECTED`가 나지 않는다. 마지막 보고 뒤 로봇의 위치 추정이 튀면 거절될 수 있고, 그때는 재시도가 새 보고로 path를 다시 만든다 |
| 목표 묶음 | `path` 모드는 잠금을 쥔 데까지 레인을 한 목표로 묶고 유턴에서만 끊는다. `point` 모드는 같은 방향 레인만 묶는다 |

## 6. 상태 값 (`/fleet/robots`)

| 값 | 항목 | 뜻 |
|---|---|---|
| `IDLE`, `PARKED`, `TO_PARK`, `TO_WORK`, `TO_OUTBOUND`, `DOCKING`, `AT_STATION` | 임무 단계 | 대기, 대기 지점, 이동 중(대기 지점·작업공간·출고), 도킹 중, 도크에서 대기 |
| `NONE`, `ERROR`, `COMM_LOST`, `RECOVERING`, `OUT_OF_SERVICE` | `fault` | 정상, 관리자 확인 필요(`fault_reason`, 지도에 오른 로봇은 자동 격리됨), 통신 두절, 복구 확인 중(통신 복구는 `CHECKING_POSE`, 레인 이탈은 `OFF_LANE`), 관리자가 치움 |
| `BLOCKED` | `fault_reason` | 막힘이 열려 있는 동안. 이때 `fault`는 `NONE` |
| `IDLE`, `MOVING`, `WAITING`, `DOCKING`, `DOCKED`, `ERROR` | `fsm_state` | 핑키가 보고한 값 그대로 |
| `BLOCKED`, `LOCALIZING` | `fsm_state` | 앞 물체로 섬, 위치를 못 잡음(제안, 팀 합의 전). `LOCALIZING`의 자세는 믿지 않는다 |
| `RECOVERING` | `fsm_state` | 핑키가 스스로 짧게 후진하고 다시 가는 중(자가 복구, 제안, 팀 합의 전). 이때 `fault`는 `NONE`이다. `fault`의 `RECOVERING`(관제가 두절이나 레인 이탈 뒤 로봇을 확인하는 중)과 이름만 같고 다른 값이다 |
| `TO_WORK`, `FILL`, `TO_OUTBOUND`, `SWAP`, `WAIT` | `task_type` | 지금 하는 일 |
| `PENDING`, `BOUND`, `FILLING`, `TO_OUTBOUND`, `SWAPPING`, `SHIPPED`, `PARTIAL`, `HELD` | 주문 | 주문 진행 단계 |
| `EMPTY`, `FULL`, `NONE` | 바구니 | 빈 바구니, 담긴 바구니, 없음 |

| `ROBOT_ISOLATED` | ERROR | 지도에 오른 로봇이 ERROR가 되어 자동 격리함(detail에 이유와 쥔 구역) |

| `ORDER_BOUND` / `ORDER_REQUEUED` | INFO | 주문을 로봇에 묶음 / 격리됐거나 치운 로봇의 주문을 되돌림 |
| `FILL_RETRY`, `SWAP_RETRY` / `FILL_FAILED`, `SWAP_FAILED` | WARN / ERROR | 팔 작업 다시 보냄 / 재시도를 다 씀 |
| `DISPATCH_RETRY` / `DISPATCH_FAILED` | WARN / ERROR | 실패한 출고 도크 호출을 다시 보냄 / 재시도를 다 씀(제안) |
| `ARM_NO_RESULT` / `ARM_LATE_RESULT` | ERROR / WARN | 취소한 팔 작업의 결과가 안 옴 / 늦게 옴 |
| `NO_ROBOT_AVAILABLE` | WARN | 주문은 있는데 쓸 수 있는 로봇이 없음 |
| `CANCEL_UNCONFIRMED` | WARN | 취소했는데 결과가 안 옴 |
| `ORDER_REPORT_REFUSED` | ERROR | central이 보고를 거절함 |

주문 관련 이벤트의 detail은 주문 ID로 시작합니다.
